# 燕窝个人博客系统 — 开发进程汇报

**文档性质**：项目进展说明（可用于课程/课题/工作汇报）  
**项目名称**：燕窝（原「墨笺」主题命名已统一为「燕窝」）  
**技术形态**：前后端分离博客系统  

---

## 一、项目概述

本项目为一套个人博客平台，实现文章展示与创作、用户注册登录、评论互动、管理员后台与简单数据可视化。前端采用 Vue 3 + Vite，后端为 Node.js + Express，数据持久化使用 MongoDB。接口风格为 REST，认证采用 JWT，前后端经 `/api/v1` 统一前缀通信。

**当前阶段目标**：在稳定跑通主流程（读文章、发文章、评论、后台管理）的基础上，完成界面统一、常用检索与数据看板，并为后续可扩展项（如动态权限、更细内容审核）预留空间。

---

## 二、技术架构简述

| 层次 | 技术选型 | 说明 |
|------|----------|------|
| 前端 | Vue 3、Vue Router、Pinia、Axios、marked、ECharts | SPA；Markdown 渲染；管理端趋势图 |
| 构建 | Vite | 开发期代理到本地后端、减轻跨域与缓存问题 |
| 后端 | Express、Mongoose、JWT、Helmet、CORS 等 | 路由分层；中间件鉴权与管理员校验 |
| 数据 | MongoDB | 文档型存储；核心实体：User、Post、Comment、Category（及预留 Role 模型） |

**部署与运行要点**：需配置 `MONGO_URI`、`JWT_SECRET`；生产环境需为 SPA 配置 History 回退与 API 反向代理。

## 三、已完成功能

### 1. 用户与认证

- 用户注册、登录，密码哈希存储。  
- 角色字段 `reader` / `author` / `admin`（与业务中「后台」与统计接口的权限判断对应）。  
- 前端通过 Pinia 保存 token 与基本信息；受保护页面（如写作、管理端）在路由层拦截。  
- 需登录的接口失败时，支持跳转登录并携带 `redirect` 回跳。  

### 2. 文章

- 文章列表（公开）：分页、按关键词搜索、按标签筛选。  
- 文章详情：按 `slug` 访问，增加阅读量，Markdown 渲染。  
- 发布文章：支持标题、正文（Markdown）、标签、封面图 URL、草稿/已发布。  
- **已处理问题**：当标题为纯中文等导致 `slugify` 空串时，后端生成回退 `slug` 并做唯一性处理，避免「slug 必填」校验失败。  
- 后台端：文章全量列表、按角色删除（软删为 `deleted` 等状态，与实现一致）。  

### 3. 评论

- 按文章拉取已审核通过评论、发表评论。  
- 已登录用户与游客（填昵称/邮箱）均可评论；与 Post 的引用关系明确。  
- 评论与 Post 的 `commentCount` 等字段在实现中已考虑一致性（以当前代码为准）。  

### 4. 标签与发现

- 公开接口提供标签统计（标签云数据）。  
- 前端提供标签页与列表内通过标签再筛选。  

### 5. 管理端与数据可视化

- 管理布局（侧栏 + 主内容区）：仪表盘、文章管理入口。  
- 仪表盘：总文章数、总用户数、待审核评论数；近 30 日新发布文章趋势（ECharts 折线）。  
- 统计与趋势接口对管理员进行鉴权。  

### 6. 界面与产品命名

- 全站统一样式主题（色板、卡片、顶栏/页脚）。  
- 品牌名称已统一为 **「燕窝」**（含页签标题、顶栏、页脚、登录注册与后台侧栏等）。  

### 7. 数据设计（E-R 概要）

- **User** 1—N **Post**（作者）。  
- **Post** 1—N **Comment**；**User** 与 **Comment** 可选关联（游客无用户 ID）。  
- **Category** 与 **Post** 为可选 1—N。  
- **Comment** 支持 `parent` 自引用，可扩展为楼中楼。  
- **Role** 模型文件存在，但**尚未**与 `User` 以集合外键方式打通，属预留或待迭代项。  

（详细实体属性与关系可单独附 E-R 图或从 Mongoose 模型导出。）

## 四、已识别限制与未展开项

| 项 | 说明 |
|----|------|
| 动态 RBAC | 当前为 `User.role` 枚举 + 路由/接口的 `admin` 判断，非可配置多角色/多权限表驱动。 |
| 分类（Category） | 模型与字段存在，业务上若未在写作/列表中完整接入，则仅为数据层能力。 |
| 评论审核流 | 状态字段已具备，管理端若未提供完整「待审列表与批量操作」，则产品闭环仍可加强。 |
| 访问统计 | 看板中趋势以「新发布文章」为维度，非独立埋点/UV 体系。 |
| 性能与运维 | 未在本汇报范围内展开压测、日志规范与 CI/CD。 |

以上可作为下一阶段需求池与验收标准。
